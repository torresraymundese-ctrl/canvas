# 导演画布一键启动器设计

## 目标

在 Windows 上提供一个位于 `D:\画布\启动画布.cmd` 的一键启动入口。用户双击后无需输入命令：画布服务自动启动，后台窗口最小化，服务就绪后默认浏览器自动打开画布页面。

## 用户流程

1. 用户双击 `启动画布.cmd`。
2. 启动器检查 `D:\画布` 中是否存在完整程序，并检查 Node.js 是否可用。
3. 启动器请求 `http://127.0.0.1:4187/api/health`：
   - 如果画布已经运行，直接打开 `http://127.0.0.1:4187/`，不创建第二个服务进程。
   - 如果画布未运行，在一个标题明确的最小化命令窗口中启动本地服务。
4. 启动器等待健康检查成功，再打开浏览器。
5. 用户关闭最小化的服务窗口即可停止画布服务。

## 实现选择

采用 ASCII 内容的 Windows 批处理启动器。它比 PowerShell 脚本更适合直接双击，也避免 PowerShell 执行策略拦截。脚本正文不包含中文字节，目标目录 `D:\画布` 通过 Unicode 字符码构造，以规避此前 Windows `cmd.exe` 对无 BOM UTF-8 中文脚本的误解析问题。

启动器支持可选的目标目录参数，便于自动测试；正常双击时使用 `D:\画布`。启动服务使用已有的 `server/index.js`，不会引入新的后台框架或安装依赖。

## 安全与错误处理

- 启动器只在 `127.0.0.1:4187` 启动本机服务，不开放局域网访问。独立使用 4187 可避开旧前端预览常用的 4173 端口。
- 启动器不读取、显示、创建或修改 API Key。
- 当前没有 `.env` 时继续使用 `mock` 模式，不产生模型费用。
- 缺少程序、缺少 Node.js、端口冲突或服务启动超时时，窗口保持打开并显示稳定的错误标识，方便截图排查。
- 重复双击不得重复启动服务。

## 文件与安装

- 新增 `scripts/start-canvas.cmd` 作为受测试的启动器源文件。
- 交付包根目录包含用户可双击的 `启动画布.cmd`。
- 安装后启动器位于 `D:\画布\启动画布.cmd`。
- 保留现有 `.env` 和 `runtime/jobs.json`；安装与启动都不得删除用户数据。

## 验证

- 自动测试使用临时画布目录和本地假服务，验证启动器能启动服务、等待健康检查并在 `--no-browser` 模式下成功退出。
- 自动测试验证已有服务时不会再次启动。
- 在 `D:\画布` 上执行 4187 端口的健康检查，确认页面返回 HTTP 200、执行模式为 `mock`、凭据状态为未配置。
- 手工验收：双击启动器，后台窗口最小化，浏览器打开画布；再次双击只打开页面；关闭后台窗口后服务停止。

## 不在本次范围

本次不创建 Windows 服务、托盘图标、开机自启、桌面应用外壳或自动写入真实模型配置。这些能力只有在一键启动稳定后才考虑。
